# mda_agent (case 7)

A minimal Managed Deep Agent, scaffolded with `mda init` and given one tool
(`tools/weather.py`) that emits the `mda:lookup_weather` marker run.

- `make services-up` runs it under `mda dev` on :2025 (cases 7a and 7b).
- `middleware/continue_trace.py` is the case-7b attempt at applying inbound
  trace context from middleware. It only activates when the caller's metadata
  carries `harness_mda_middleware`.
- `scripts/run_mda_patched.sh` serves a copy of the compiled build on :2026 with
  the generated graph factory wrapped in `tracing_context` (case 7c). That file
  is regenerated by `mda deploy`, so this is evidence for a runtime change, not
  a workaround to ship.

`.env` here is a symlink to the repo-root `.env`; `mda dev` copies it into the
gitignored `.mda/build/`.
